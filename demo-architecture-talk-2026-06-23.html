01 · End-to-end architecture flow

A single flow explains the platform, project assets, execution runtime, and quality gate.

qa-harness supplies the reusable system. west-kowloon supplies project facts. Dashboard and automation convert those assets into run history, evidence, observability signals, and gate output.

The flow intentionally uses one diagram: platform ownership, project ownership, runtime execution, observability, and governance are shown as one delivery system.

02 · Runtime tool architecture

Vite, FastAPI, Behave, Pytest, Locust, SQLite, and observability services form the execution toolchain.

The browser talks to the Vite frontend. Vite proxies API and WebSocket traffic to FastAPI. FastAPI orchestrates Behave, Pytest, and Locust, then persists results and evidence for dashboard review.

This diagram focuses on tooling boundaries: Vite renders the UI, FastAPI orchestrates work, Behave/Pytest/Locust execute tests, and SQLite/artifacts/observability services retain the evidence.

03 · Testing pyramid

Coverage is layered so each test type proves the right level of risk.

Fast API checks protect the foundation. Mixed API+UI scenarios validate important business chains with final UI proof. Full UI E2E is reserved for journeys where browser behavior is the risk.

The pyramid keeps UI E2E focused while preserving high confidence through API and mixed-layer checks.

04 · Component model

The implementation is compact: two roots, one dashboard, layered automation, and a strict evidence model.

qa-harness

Reusable QA system: workflow, templates, skills, gate scripts, Behave/Pytest/Locust runtime, dashboard, and infra.

west-kowloon

Project workspace: source documents, Website modules, test design, project-specific automation, execution evidence.

Dashboard

Vite + React frontend on 5174, FastAPI backend on 8002, SQLite persistence, WebSocket run logs.

Automation layers

API smoke, API contract, API functional, API+UI mixed, UI E2E, performance workloads.

Observability

Prometheus, Grafana, and Loki provide metrics, panels, and log visibility for performance-oriented runs.

Quality gate

Validates schema, traceability, evidence completeness, and workflow coverage before quality closure.

Traceability key

  • Test cases carry stable case IDs, for example SIT-TC-WEB-AUTH-009.
  • Feature scenarios and tags reference the same case IDs.
  • Dashboard results store run and scenario history in SQLite.
  • Evidence rules require environment, actual result, comments, and screenshots where applicable.
The platform distinguishes execution success, automation coverage, and evidence completeness. That separation is important for release decisions because a run can pass while supporting evidence still needs remediation.
