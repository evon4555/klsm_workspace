## 需求背景与概述
现有票务系统中，"会员权益"仅面向企业内部自有会员。近期出现新的业务场景：合作客户希望将其**兄弟公司的签约业主**（外部身份）引入平台，使其享受与内部会员同等的权益服务。

为支撑该场景，本期将原"优先购合作方"能力**泛化为完整的合作方会员身份系统**：

1. 合作方会员不再单独服务于优先购，而是作为一个**跨权益模块的会员身份来源**，与内部会员对齐，可接入优先购、会员专享项目、会员专享商品、促销活动等多个权益模块。
2. 合作方会员身份的来源支持四种验证方式：BIN 校验、白名单导入、OAuth 跳转、API 接口。本期落地 **BIN 校验**与 **API 接口**两种，白名单与 OAuth 标注本期不做。
3. 各权益模块在"限定会员等级"处，新增对**合作方会员等级**的支持，与内部会员等级以独立配置区的形式并列。



本版本只做

1. bin库管理
2. 合作方会员只支持bin校验模式
3. 权益只做优先购



## 功能设计
# 会员管理
## 1.1 合作方会员管理
入口：会员管理 → 合作方会员管理

合作方是合作方会员身份的承载主体。一个合作方下挂若干"等级"，等级是被各权益模块引用的最小身份单位（地位等同于内部会员等级）。

### 1.1.1 列表页
<img src="https://cdn.nlark.com/yuque/0/2026/png/61042497/1780901383905-fa0998b2-5f26-4f2f-be88-67c12a44eedb.png" width="1600.0000423855263" title="" crop="0,0,1,1" id="u308cf6b8" class="ne-image">





显示内容：已创建的合作方，以卡片形式展示。每个合作方卡片包含：

+ 头部：Logo、合作方名称、验证方式标签（BIN 校验 / 白名单 / OAuth / API）、等级数量、**总状态开关**（启用 / 停用）
+ 副信息行：合作起止时间、关键摘要（BIN 类显示"共 N 个 BIN 段分布在 M 个等级 · 凭证 X 天"；API 类显示接口域名 + 凭证天数；白名单/OAuth 显示对应摘要）
+ 等级表格：列为「等级名称 / 等级 ID / 关键参数 / 操作」，等级行**不含状态列**
+ 操作：+ 新增等级、编辑（合作方）、删除（合作方）

筛选项：合作方名称、验证方式、状态（启用 / 停用）。

**总状态开关说明**：状态收敛在合作方层（启用 / 停用），等级不再单独设状态。停用合作方后，其下所有等级在各权益模块中失效。

### 1.1.2 新建 / 编辑合作方
底部：取消（返回列表）、保存。

### 1.1.4 业务规则
| 编号 | 规则 |
| --- | --- |
| PT-01 | 合作方名称在企业内唯一 |
| PT-02 | 一个合作方只能配置一种验证方式；一旦该合作方下创建了等级，验证方式锁定不可修改 |
| PT-03 | 等级 ID 在同一合作方内唯一，创建后不可修改 |
| PT-04 | 停用合作方后，其下所有等级在优先购/会员专享/促销等模块中失效 |
| PT-05 | 合作方被任一权益模块引用（等级被引用）时不可删除，需先解除引用 |
| PT-06 | 删除合作方将级联删除其下所有等级及相关配置，删除前需二次确认 |
| PT-07 | BIN 校验类等级必须至少关联 1 个 BIN 段 |

## 1.2 BIN 库管理
入口：会员高级管理 → BIN 库管理

BIN 库是全平台共用的基础数据，独立于合作方维护，可被多个合作方的等级引用。

<img src="https://cdn.nlark.com/yuque/0/2026/png/61042497/1780901638785-1308e368-4886-41c8-9457-6bff6148564b.png" width="1600.0000423855263" title="" crop="0,0,1,1" id="u2a19c44c" class="ne-image">



### 1.2.1 列表页
显示内容：BIN 段列表（表格）。列为：

+ **BIN 段 / 卡属性**：BIN 号为主，下方一行展示三个标签——卡组织（自动识别）、卡类型、卡等级
+ **长度**：由 BIN 号位数自动判断（支持 6 / 8 位等不同长度，不固定）
+ **发卡行**
+ **发卡地**
+ **引用情况**：展示引用该 BIN 段的"合作方 · 等级"，未引用则显示"未引用"
+ **操作**：编辑、删除

筛选项：BIN 段 / 发卡行（关键词）、卡组织、发卡行、卡类型、发卡地、卡等级。

### 1.2.2 新建 / 编辑
<img src="https://cdn.nlark.com/yuque/0/2026/png/61042497/1780901677257-d3af46e7-a0c2-4326-97ca-4d3ef84866fd.png" width="622.2222387054825" title="" crop="0,0,1,1" id="uc96ced9e" class="ne-image">

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| BIN 段 | 文本（数字） | 是 | —— | 长度由位数自动决定，支持 6 / 8 位等；编辑时不可修改 |
| 卡组织 | 自动识别（只读） | —— | —— | 系统按 BIN 号开头自动识别（见下），运营不填 |
| 发卡行 | 文本 | 是 | —— | 如"汇丰银行 HSBC" |
| 卡类型 | 单选（信用卡 / 储值卡 / 借记卡） | 是 | 信用卡 | 用于在 BIN 选择器中辅助筛选，区分权益资格 |
| 发卡地 | 文本 | 是 | —— | 如"中国香港" |
| 卡等级 | 单选（普卡 / 白金 / 钻石 / 黑金） | 是 | 普卡 | 参考分类，辅助运营在配等级时挑选 BIN |


**卡组织自动识别规则**（按 BIN 号开头，遵循 ISO/IEC 7812）：

| 开头 | 卡组织 |
| --- | --- |
| 4 | Visa |
| 51–55 / 2221–2720 | Mastercard |
| 62 / 81 | 银联 UnionPay |
| 35 | JCB |
| 34 / 37 | American Express |
| 36 / 38 | Diners Club |
| 65 / 6011 | Discover |


### 1.2.3 业务规则
| 编号 | 规则 |
| --- | --- |
| BIN-01 | BIN 段在库内唯一 |
| BIN-02 | 卡组织由系统按 BIN 号开头自动识别，只读展示，运营不可编辑 |
| BIN-03 | BIN 长度不固定，跟随每条 BIN 段自身位数；不要求统一为 8 位 |
| BIN-04 | 校验时采用**最长前缀匹配**：同一卡号命中多条 BIN 段时，优先归入更具体（更长）的那条 |
| BIN-05 | 一个 BIN 段在同一合作方下应只属于一个等级，避免校验冲突 |
| BIN-06 | 删除被等级引用的 BIN 段时需提示，删除后该 BIN 段从所有引用等级中移除 |
| BIN-07 | 8 位 BIN 本身不携带卡等级信息，等级归属靠运营依据发卡行清单手动挂载 |

# 权益管理（接入合作方会员等级）
现有优先购、会员专享项目、会员专享商品、促销活动均已支持内部会员等级。本期在各模块的"会员等级"配置处，新增对**合作方会员等级**的支持。合作方等级与内部等级以**独立配置区**的形式并列（地位对等，可分别配置）。

## 2.1 优先购配置
入口：权益管理 → 优先购配置

<img src="https://cdn.nlark.com/yuque/0/2026/png/61042497/1780976953708-58dae575-a1d6-4067-9b34-31148cf239b3.png" width="1626.6667097586185" title="" crop="0,0,1,1" id="u6afcb156" class="ne-image">

<img src="https://cdn.nlark.com/yuque/0/2026/png/61042497/1780976971679-7081cc62-c403-4992-b504-bf1c2330be47.png" width="844.4444668145833" title="" crop="0,0,1,1" id="uecbc1949" class="ne-image">



在项目优先购的"细则"中，每条规则可绑定一个合作方等级，配置优先购提前时间。

**细则字段**（每条规则一行）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| 合作方 | 下拉单选 | 是 | 仅列启用状态的合作方 |
| 等级 | 下拉单选 | 是 | 选定合作方后联动其等级 |
| 提前时间 | 数字（分钟） | 是 | 该等级用户可提前进入优先购的时长 |


**限购规则**：不限购 / 优先购期间限购；限购层级：单项目 / 每场次；每用户最多购买 N 张票。





# 用户端（webSite）
## 3.1 我的权益身份
入口：个人中心 →「我的权益身份」（独立入口）

用户在此**主动、提前**完成合作方身份的绑定与管理。身份绑定与下单消费解耦。

**列表**：展示用户已绑定的身份卡片，每张含：合作方 · 等级、验证方式标签、凭证状态（BIN/API 显示"凭证 X 天后失效"；白名单/OAuth 显示"永久有效"）、绑定时间。操作：**解绑**。底部「+ 添加新身份」。



<img src="https://cdn.nlark.com/yuque/0/2026/png/61042497/1780905601725-a574b415-bbf1-4db8-8c6c-bab616579b35.png" width="2133.3333898473684" title="" crop="0,0,1,1" id="u50471ddc" class="ne-image">

**绑定流程**：

1. 点「+ 添加新身份」选择合作方
2. 按该合作方验证方式提交凭证：
    - **BIN 校验**：输入银行卡号（不固定位数），系统截取前缀做最长前缀匹配
    - **API 接口**：按合作方配置的"用户需填字段"动态渲染表单，用户填写后调接口核验
    - **OAuth / 白名单**：本期不做
3. 核验通过 → 绑定身份 + 生成凭证（BIN/API 按天数，白名单/OAuth 永久）；核验失败 → 提示失败，可重试

<img src="https://cdn.nlark.com/yuque/0/2026/png/61042497/1780905620268-ab6e16c4-6595-4a63-9ac2-b746d46488e0.png" width="2133.3333898473684" title="" crop="0,0,1,1" id="ua6f08f16" class="ne-image">





## 3.2 下单时权益判定
用户正常浏览 / 下单时，系统自动判定权益，不打断主流程：

1. 判断用户已绑定身份或会员等级或会员卡权益是否命中该优先购权益（用户满足身份条件且配置的优先购开始时间满足当前时间）
    - 命中 → 享受对应权益（提前购 / 专享价 / 折扣）
    - 未命中 → 按普通价购买（**不打断**），可弱提示"绑定 XX 身份可享专享"
2. 若用户同时持有内部会员 + 多个合作方身份且命中多条规则，默认取最优权益。同时扣减该权益绑定的优先购次数



当银行卡优先购权益与促销活动权益冲突时：

若用户在下单时，使用的是银行卡优先购权益，订单上绑定了一个mid值，若用户可享用的银行卡促销活动的mid值与该优先购mid值一致，则用户可正常选用该银行卡促销活动，若不一致，则该银行卡促销活动不可选中。

# 业务流程
## 4.1 运营配置流程
维护 BIN 库 → 创建合作方（选 1 种验证方式）→ 配置等级（每级独立配置 BIN+支付 / 匹配值 / 名单）→ 等级接入权益（优先购 / 会员专享项目 / 会员专享商品 / 促销活动）。

## 4.2 用户使用流程
**身份绑定（用户主动，提前完成）**：进入「我的权益身份」→ 选择合作方 → 按验证方式提交凭证 → 核验通过 → 绑定身份 + 生成凭证。

**下单消费（系统自动判权益）**：用户正常下单  → 判断会员是否命中 → 命中享受权益 / 未命中按普通价（不打断）。已绑定的身份在下单的权益判定环节被读取参与判定。

# 关键设计决策（备查）
| 编号 | 决策 | 说明 |
| --- | --- | --- |
| KD-01 | BIN 关联在等级层 | 8 位 BIN 不携带等级信息，靠运营把发卡行清单的 BIN 段挂到对应等级 |
| KD-02 | 支付配置在等级层 | 一个等级一套支付网关 + 商户号，等级下所有 BIN 共享 |
| KD-03 | BIN 长度不固定 + 最长前缀匹配 | 长度跟随每条 BIN 段自身位数；同一卡号命中多条时取最具体（最长）的 |
| KD-04 | 卡类型靠拆等级区分资格 | 如"浦发信用卡"与"浦发储值卡"建成不同等级，权益层不加卡类型过滤，资格自然区分 |
| KD-05 | 卡组织自动识别 | 系统按 BIN 号开头识别（ISO/IEC 7812），运营不填，只读展示 |
| KD-06 | 一合作方一验证方式 | 有等级后锁定不可改 |
| KD-07 | 内部会员 ↔ 合作方会员对等 | 合作方等级与内部会员等级地位相同，各权益模块以独立配置区并列引用 |
| KD-08 | 状态收敛在合作方层 | 合作方有启用/停用总开关，等级不单独设状态 |
| KD-09 | 身份绑定与消费解耦 | 用户在个人中心主动提前绑定；下单时系统读取已绑定身份做权益判定，未命中不打断 |
| KD-10 | 多身份取最优 | 用户同时命中多条权益规则时，默认取最优 |

# 多语言支持汇总
以下录入需要支持多语言

+ 合作方会员：合作方名称；备注
+ 等级配置：等级名称
