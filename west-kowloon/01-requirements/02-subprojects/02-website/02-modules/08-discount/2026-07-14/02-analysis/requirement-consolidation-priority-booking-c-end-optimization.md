## 4. 差异项

### 4.1 与上一版本对比

| 编号 | 能力 | 2026-06-25 旧行为 | 2026-07-14 新行为 | 用例影响 |
|----|----|----|----|----|
| D-prev-1 | 入口 | 从个人中心 `我的权益身份` 主动绑定身份，再由下单读取权益 | 从项目详情页展示优先购政策，当前页完成验证 / 获取资格 / 登录引导 | 新增项目详情页主流程；`我的权益身份` 保留为本轮同步、查看和解绑路径 |
| D-prev-2 | 优先购类型 | 重点是银行卡 / 合作方会员优先购 | 同页展示银行卡、会员卡、储值卡、会员等级四类优先购 | 新增多类型展示、排序、状态用例 |
| D-prev-3 | 银行卡验证 | 倾向旧版身份绑定和完整卡号 / BIN 匹配 | 项目页 P2 弹窗输入银行卡前 8 位，验证后刷新优先购状态并展示有效期 | 重写验证用例，不机械 patch |
| D-prev-4 | 账号状态 | 旧版用例主要围绕已登录用户 | 新版明确未登录、游客/临时账号、注册用户 | 新增账号状态矩阵 |
| D-prev-5 | 购物车 | 旧版 workbook 有购物车 / checkout E2E 参考 | 新版优先购项目与购物车无关，未到公众开售时隐藏购物车 icon | 旧购物车断言要改；后续 workbook 黄色标记 |
| D-prev-6 | 购票链路 | 旧版强调 checkout 权益判定和次数扣减 | 新版强调购票入口和交易前复核 | 新增门票 / 座票拆分的入口复核用例 |
| D-prev-7 | 支付风险 | 旧版有银行卡优先购 × 银行卡优惠 `mid` 冲突 | 新版强调预验证不等于支付成功，支付阶段再次校验 | Website 只测成功 / 失败可见结果；旧 `mid` 规则保留为参考，不展开新矩阵 |
| D-prev-8 | 多语言 | 旧版测合作方 / 等级字段渲染 | 新版有优先购区域、弹窗、按钮、提示和 `Priority Booking` 文案 | Q-10 已确认本轮不展开多语言 / fallback 用例 |
