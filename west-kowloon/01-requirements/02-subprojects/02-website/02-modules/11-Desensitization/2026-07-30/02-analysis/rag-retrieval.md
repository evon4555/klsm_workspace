## Reuse / Update / Create 判断

- Reuse：复用历史用例中的页面入口、门票/座票数据准备方式和角色背景。
- Update：当前不回写旧日期包；签字后在新包中建立跨模块用例，并在 `Collected from` 记录受影响旧用例 ID。
- Create：Website、PDA、后台、BI、KMS、权限、审计和报表导出均需要新增覆盖。
- Ticket type split：订单、票夹、入场码、PDA 扫码、后台订单必须分别考虑 Admission ticket 和 seat-selection ticket。

## 发现的主要差异

1. 旧手机号示例 `138****8000` 是前 3 后 4；新需求文字写“前 3 后 3”。
2. 新需求中的中国号码示例 `+8613800008000 -> +861*****000` 与国际号码示例 `+852 9123-4567 -> +85****567` 的可见前缀计算方式不一致。
3. 旧门票/座票用例中的姓名和证件号精确规则为 TBD；本包规则文件虽然给出示例，但阶段结论又写“先从手机号、邮箱开始”。
4. 现有用例没有覆盖 PDA、后台会员 360、会员卡列表/订单、BI 自定义报表、Dashboard 无 PII 检查、KMS 故障和订单访问审计。

## 结论

本需求不应只修改一两个 Website 用例。签字后应生成新的中文跨模块用例集，并保留现有用例作为回归入口与差异证据。
